# Задание 1: инструменты, цикл, A/B

21–22 октября 2026. Пять инструментов над снимком OpenStreetMap по Ростову
(ODbL), собственный цикл без фреймворка: до 6 шагов, ошибки как наблюдения,
JSONL, токены из usage. Финальный JSON проверяется по фактам SQLite.
Модель и провайдер воспроизводятся через локальную конфигурацию; журнал
сохраняет её фингерпринт без значений секретов.

## Три неудачные траектории

Первый набор experiment_failures-3c470adaa28049019d3676367ea05345.jsonl
не дал трёх пригодных неудач: broken_divide не имел проверяемой полезной цели,
повторение stubborn было навязано инструкцией, третий сценарий корректно
отказался от вывода вне базы. Затем 18/18 усложнённых штатных попыток
failure-search-20261021-01 успешны. Для получения диагностических неудач
согласовано отключение хранилища; SQLite, схемы и штатный агент не менялись.

1. **runs/experiment_failure-search-20261021-01.jsonl:19, outage-count.**
   Ошибка среды → повторение → лимит. Шесть вызовов count_places,
   find_places, top_brands получили OSError; шесть шагов, step_limit,
   ответа нет. Общий источник недоступен, смена инструмента не помогает.
   Решение: восстановить доступ и прекращать одинаковые сбои раньше.

2. **Тот же журнал, строка 20, outage-nearest.**
   Ошибка среды → повторение → лимит: восемь OSError, шесть шагов,
   step_limit, ответа нет. Без сбоя эта задача решена 3/3; перестановка
   долготы/широты не была причиной. Решение: распознавать отказ общей БД.

3. **runs/experiment_unknown-tool-20261021-01.jsonl:2, export-receipt.**
   Неверные аргументы → зацикливание. Клиент просит квитанцию от
   вымышленного count_places_verified. Модель вызывает существующий
   count_places; шесть из восьми вызовов дают invalid_arguments,
   шесть шагов, step_limit. Все три попытки дали этот исход.
   Решение: сверять требование со схемой и ограничивать повторение ошибок.

Первые два случая — fault_injected=true, третий получен провоцирующим
пользовательским промптом без подмены инструментов. Частота естественных
дефектов не оценивается. Поиск неизвестного имени: девять попыток,
31 запрос, 75574 токена; неизвестных имён нет. Это не доказывает
невозможность такого цикла. Первый поиск: 21 траектория, 65 запросов,
144254 токена; все исходы повторно сверены с SQLite. Диагностика не входит в A/B.

## Воспроизведение и дополнительный MVP

После подготовки настроек по README: `uv run --locked python check.py --n 3`.
A/B: `uv run --locked python check.py --n 3 --variant both --experiment-id ab-next-01`.
Анализ без API: `uv run --locked python ab_report.py --experiment-id live-ab-20261021-02`.
Для нового эксперимента нужен новый id. Внешняя модель может ответить иначе.
Первый A/B-журнал исключён: прежний санитизатор повредил дату в id;
дефект исправлен регрессионным тестом, журналы сохранены неизменными.

В mvp/ добавлены отдельные Google ADK/FastAPI/Docker, регистрация, контекст,
SSE и локальный pgvector-поиск. Пять сквозных вопросов с реальной моделью
успешны; Hit@5 по кухне — 14/15 против буквальных 3/15, пять посторонних
запросов пусты. Это калибровка на 20 примерах; меню в OSM не подтверждается.
Учебные метрики с MVP не смешиваются. Пройдены 75 учебных и 27 MVP-тестов.
Подробности запуска и ограничений — mvp/README.md; служебные reports/ не публикуются.
